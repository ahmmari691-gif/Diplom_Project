# Три учебных аккаунта

Учебный режим использует отдельный файл `study.sqlite3`, игнорирует `DATABASE_URL` и не изменяет внешнюю базу. Он не переносит старые заказы. Обычная авторизация и права доступа сохраняются; старый переключатель ролей `DELO_DEMO` не используется.

## На любом компьютере

Нужны Python 3.12 и Node.js 24. Из папки `delo-doma 2`:

```sh
python -m venv .venv
# macOS / Linux:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей команды:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
cd frontend
npm install
npm run build
cd ..
python run.py --study
```

Открыть http://127.0.0.1:8000. При первом старте создаются:

| Роль | Email | Пароль только для localhost |
|---|---|---|
| Бизнес | business@demo.local | Study-Business-2026! |
| Менеджер | manager@demo.local | Study-Manager-2026! |
| Администратор | admin@demo.local | Study-Admin-2026! |

У бизнеса будет учебная кондитерская и товар за 6500 ₸. Для первого заказа выберите дату хотя бы через 24 часа. Аккаунты разных компьютеров независимы. После обычного перезапуска локальные данные сохраняются. Не удаляйте `study.sqlite3` и `.local`: в `.local` находятся локальные ключи шифрования. Эти файлы не передаются другим людям и не коммитятся.

Пароли можно заранее задать в `.env` через DELO_STUDY_BUSINESS_PASSWORD, DELO_STUDY_MANAGER_PASSWORD и DELO_STUDY_ADMIN_PASSWORD. Команда не перезаписывает пароль или права существующего аккаунта; изменение переменной окружения не является сбросом пароля.

## На Render без внешней базы

После загрузки изменённого кода в репозиторий в настройках существующего сервиса Environment установить:

```text
DELO_STUDY_MODE=1
DELO_DEMO=0
DJANGO_DEBUG=0
DELO_STUDY_BUSINESS_PASSWORD=<свой пароль бизнеса>
DELO_STUDY_MANAGER_PASSWORD=<свой пароль менеджера>
DELO_STUDY_ADMIN_PASSWORD=<свой пароль администратора>
```

Задать три собственных пароля длиной не менее 8 символов. Локальные примеры в серверном режиме запрещены. Сохранить существующие DJANGO_SECRET_KEY и DATA_ENCRYPTION_SECRET / DATA_ENCRYPTION_KEY; их значения не должны меняться при рестарте. Выполнить redeploy. DATABASE_URL можно оставить: в этом режиме он игнорируется. Не удаляйте внешнюю базу — переключение режима не требует её уничтожения.

Скрипт старта запускает миграции и восстанавливает недостающие аккаунты из этих настроек. Даже если бесплатный Render очистит SQLite, после старта логины и заданные в Environment пароли будут снова доступны. Сохранность новых заказов, смены паролей через приложение и прав после очистки базы не гарантируется: восстановится начальное состояние. Для постоянного хранения этих изменений требуется постоянная база или постоянный диск.

Это отдельная учебная база. Не включать режим на сервисе с реальными данными. Для возвращения к внешней базе установить DELO_STUDY_MODE=0 и рабочий DATABASE_URL, затем перезапустить. Учебные данные автоматически не копируются.

Ограничения Render: https://render.com/docs/free#local-files-lost-on-redeploy

## Ручной старт без run.py

Сначала задать DELO_STUDY_MODE=1 в окружении или `.env`, затем:

```sh
python manage.py migrate
python manage.py ensure_study_accounts
python manage.py runserver
```

Повторное создание не стирает существующие аккаунты, каталог или заказы и не возвращает отозванные права менеджеру. После полного удаления SQLite восстановятся исходные аккаунты и один товар. `.env`, базы, локальные ключи и пароли сервера не включать в Git или архив для передачи.
